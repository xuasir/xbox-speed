# 诊断与验收

LuCI 的“环境检测”提供快速初查、后台完整验收、历史验收查看及脱敏报告下载。运行状态区显示最近完整测速和最近活动，运行日志页提供分组结果、应用状态、时间、退出码和持久保存警告。

“日志模式”默认选择简洁，保存并应用后生效。日常使用简洁模式，排查期间切换详细模式。页面稳定空闲时每 30 秒刷新状态，执行任务、读取失败或服务状态异常时每 5 秒刷新。

## 任务与错误

后台请求返回 `accepted` 和 `task_id`，任务进入 `queued → running → 终态`。终态包括 `success`、`partial`、`failed`、`cancelled`、`skipped` 和 `interrupted`；每组测速及应用验收有独立结果。摘要仍为运行状态而对应进程已消失时，读取端标为 `interrupted / PROCESS_MISSING`。

分组字段包括 `cn`、`com`、`store`、`ps`、`xbox_old`、`switch`。单组后台操作使用 `test_store`、`test_ps`、`test_xbox_old` 与 `test_switch` 固定 RPC 动作。每组保留独立状态、失败代码、节点与有效样本数，取消任务时保存对应组的终态。

命令行测速和 `check` 使用以下退出码：

| 退出码 | 含义 |
|---|---|
| 0 | 请求动作完成，具体适用范围见分组与验收结果 |
| 1 | 测速、配置、应用或明确的验收项失败，也用于请求的测速功能全部关闭 |
| 2 | 部分测速成功，或验收仍有警告、未知项 |
| 124 | 服务操作超过期限，等待的子进程已终止；清理记录保留 |
| 130 | 任务取消 |

curl 错误同时记录 HTTP、退出码、字节、耗时和原始错误摘要。常见代码及处理：

| 代码 | 处理建议 |
|---|---|
| `DNS_RESOLVE_FAILED` | 检查上游 DNS 和域名 |
| `CONNECT_FAILED` | 结合原始错误检查节点、路由和防火墙 |
| `TIMEOUT` | 检查连接耗时、总耗时及下载字节，确认连接或传输阶段 |
| `TIME_LIMIT_WITH_DATA` | 已取得足够的 206 样本，可用于测速排名 |
| `HTTP_NOT_FOUND` / `RANGE_INVALID` | 检查该节点的测试资源与起始偏移 |
| `HTTP_FORBIDDEN` | 检查 Host 与节点资源兼容性 |
| `RANGE_IGNORED` / `INSUFFICIENT_DATA` | 检查 Range 支持及实际返回的数据量 |
| `INVALID_SPEED` | curl 速度缺失或为零，重新测量 |
| `STORE_LINK_FETCH_FAILED` | 商店签名链接接口暂时不可用；检查 HTTPS、CA 证书与网络，当前节点保留 |
| `STORE_LINK_INVALID` / `STORE_LINK_EXPIRED` | 检查包大小、平台域名、有效期或手动签名链接 |
| `PARTIAL_COVERAGE` | 主资源已通过，部分域名资源兼容性待通过；查看该组域名结果 |
| `RESOURCE_NOT_CONFIGURED` | 填写 PlayStation 对应域名的实际资源后重新校验 |
| `OPTIONAL_GAME_RESOURCE` | Switch 游戏域名采用默认节点映射；填写游戏链接可开启增强资源校验 |
| `STAGE_FAILURE_SUMMARY` | 简洁模式的同阶段失败次数汇总；每类失败的首个完整样本保留在前文 |
| `FIREWALL_UNREADABLE` / `FIREWALL_PARTIAL_READ` | 检查工具与读取权限，当前入口状态待确认 |
| `SERVICE_TIMEOUT` | 检查 `ps w` 与服务锁持有进程；旧版锁泄漏按[恢复步骤](UPGRADE_LOCK_RECOVERY.md)处理 |
| `SERVICE_STOP_INCOMPLETE` | 根据实际解析进程的二进制、配置路径和状态检查停用结果 |
| `REDIRECT_UNAVAILABLE` | 检查独立服务端口、专用 IPv4、LAN 地址以及 nftables / iptables |
| `REDIRECT_NOT_RUNNING` / `REDIRECT_LISTENER_MISSING` / `REDIRECT_RULES_MISSING` | 检查独立 uhttpd、LAN 与回环监听及专用转发，重新应用配置 |
| `REDIRECT_REQUEST_FAILED` / `REDIRECT_MISMATCH` | 检查专用地址 80 入口、独立 Web 目录及实际 302 响应 |
| `REDIRECT_STILL_RUNNING` / `REDIRECT_RULES_REMAIN` | 根据进程身份和规则所有权检查停用清理，处理错误后重试 |

`/etc/init.d/xbox-accel stop`、`shutdown`、`disable` 默认期限为 60 秒，启动、重启、重载和开机恢复为 120 秒；超时清理可能额外耗时约 1 秒。停止后会查验实际解析进程，覆盖 procd 注册信息与 PID 文件遗失的情况。服务清理错误会保留失败退出码，重启在停止失败时中止。

任务日志先写入插件自己的活动日志；系统 syslog 写入最多等待两秒。syslog 服务阻塞时，测速结果和任务终态继续保存。取消流程使用 BusyBox 支持的整数秒计时，给后台任务最多三秒完成终态记录。

## 完整验收范围

验收分别汇总路由器链路、测试资源、直连集合，另列实际流量与 Xbox 待确认状态。资源校验失败或直连集合缺少应有节点会进入任务失败结果；查询超时等未知项进入部分完成结果。

启用的下载域名、四个备用 CDN 和三个 SRV 名称会按当前模式逐项检查。独立解析实例、主 DNS 和最多三个已识别的 DNS 重定向入口分别查询 A、AAAA、SRV，每项展示预期与实际值。超过入口上限、DNAT 目标待解析、域名兼容性失败以及功能关闭均明确列出范围。

com→cn 使用独立 uhttpd，默认服务端口 `18081`，专用虚拟地址 `192.0.2.1`。初查分别检查参数、进程与转发规则；完整验收从路由器访问专用地址的 80 入口，核对 302、国内目标及原始路径和查询参数。OUTPUT 自测与 LAN PREROUTING 规则分别检查，LAN 客户端的实际路由需额外确认。旁路由部署应将专用地址的下一跳指向插件所在设备。

防火墙重载会通过插件持有的 include 恢复专用规则；应用锁已被配置操作持有时，重载入口立即返回，由正在执行的应用操作完成恢复。停用验收核对独立进程、专用转发和重载入口均已清理；旧版主 uhttpd 的 404 配置恢复仍保留清理失败记录供重试。

新平台按域名验证各自的资源。Switch 默认映射的三个游戏下载域名参加完整 A/AAAA 验收；游戏资源增强校验为可选项，留空时记录 `OPTIONAL_GAME_RESOURCE` 并跳过资源请求。填写链接后独立验证实际游戏资源，路径或签名改变会使旧摘要失效；失败域名走上游，删除链接后恢复默认映射。公开资源可用性、默认 DNS 映射与实际游戏资源验证分别表达，设备实际效果由客户端确认。商店接口获取失败与 CDN 资源验证失败分别记录。平台配置、节点、Switch 接管域名与验证摘要参与配置签名，历史验收结果据此判断适用时刻。

LuCI 按入口折叠逐域名结果，摘要列出总数与状态数量，通过组默认收起，异常组自动展开。域名接管范围集中显示，完整验收报告保留每项原始结果。简洁日志保留验收摘要和异常项，详细日志同时记录正常的逐项结果。

`psw_white` 成员检查提供集合配置证据。Xbox 实际路径需要客户端观测：

1. 在 Xbox 所在网络确认实际使用的 DNS，读回对应下载域名，核对选中地址与 AAAA 状态。
2. 开始下载后观察实际目标 IP、Passwall 规则命中和代理流量，确认本次连接的分流路径。
3. 下载同一游戏，对比启用前后的稳定速度；节点变更后暂停并继续下载，使新连接使用新的解析结果。

## 持久记录与导出

| 路径 | 内容与保留方式 |
|---|---|
| `/tmp/xbox-accel/activity.log` | 本次开机日志，任务结束后保留 500 行 |
| `/etc/xbox-accel/activity-last.log` | 最近一次需要持久保存的任务快照，最多 500 行及 128 KiB |
| `/tmp/xbox-accel/live-task.json` | 本次开机最近活动，包含简洁模式的正常健康检查 |
| `/etc/xbox-accel/last-task.json` | 最近一次需要持久保存的活动摘要 |
| `/etc/xbox-accel/last-speed-task.json` | 最近完整测速摘要，健康检查及报告导出分别记录 |
| `/etc/xbox-accel/last-application.json` | 最近完整验收及检测配置签名 |
| `/tmp/xbox-accel/diagnostic-report.json` | 经过 JSON 文件校验的脱敏导出报告 |

持久文件原子替换并使用私有权限。简洁模式下，正常健康检查仅更新内存摘要与一条终态日志；告警、重新测速、配置修复及其他任务保存到闪存。重试后恢复的健康检查也保存告警和任务摘要。详细模式下每次健康检查均保存。重启后读取最近一次持久保存的活动；正常健康检查的内存记录保留至关机。

日志快照在需要持久保存的任务结束时更新，测速、应用、验收和报告等任务还会保存开始记录，便于识别意外中断。存储写入失败会在摘要中提示；“清空日志”清除内存日志及持久日志快照，任务摘要继续保留。LuCI 按当前模式过滤已有详细日志，脱敏导出使用保留的原始日志。

报告只收集插件配置白名单、任务及验收记录和插件日志。地址使用一致别名，URL 路径和参数隐藏，URL 认证信息移除；代理配置、Wi-Fi 密码及系统设备标识均在收集范围之外。导出成功表示报告已生成，各层检测结论保留原始状态。分享前检查报告内容。
